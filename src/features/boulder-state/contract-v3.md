# Boulder State v3 Storage Contract

> **Status**: DESIGN-ONLY — no implementation code.
> **Schema version**: 3
> **Date**: 2026-05-13

## 1. Overview

v3 eliminates the mirror-field anti-pattern in `BoulderState`. In v2, `BoulderState` duplicated every field from `BoulderWorkState` at the top level (active_plan, plan_name, status, session_ids, etc.), requiring constant synchronization via `projectWorkToMirror` / `buildWorkFromMirror`. v3 makes `BoulderState` a pure container — the only source of truth for work state is `BoulderWorkState`, stored as individual JSON files.

### Key Changes from v2

| Aspect | v2 | v3 |
|--------|----|----|
| Storage | Single `.sisyphus/boulder.json` | Individual `.sisyphus/boulder/{work_id}.json` files |
| Session lookup | Scan all works' `session_ids` arrays | O(1) via `.sisyphus/boulder/index.json` |
| Mirror fields | `BoulderState` duplicates `BoulderWorkState` fields | `BoulderState` has only `schema_version` + `works` |
| Concurrent safety | Single-file write contention | Per-work file isolation |
| Corruption scope | One corrupt file = all works lost | One corrupt file = one work lost |

## 2. File Path Conventions

```
.sisyphus/
├── boulder/                    # BOULDER_DIR
│   ├── index.json              # BOULDER_INDEX_FILE — session→work lookup
│   ├── {work_id}.json          # Individual BoulderWorkState files
│   └── .migrated               # BOULDER_MIGRATED_MARKER — v2→v3 complete
├── boulder.json                # v2 legacy file (backed up to .v2.bak after migration)
├── plans/                      # Prometheus plan files (unchanged)
└── notepads/                   # Notepad files (unchanged)
```

### Path Constants

```typescript
BOULDER_DIR              = ".sisyphus/boulder"
BOULDER_INDEX_FILE       = "index.json"
BOULDER_INDEX_PATH       = ".sisyphus/boulder/index.json"
BOULDER_MIGRATED_MARKER  = ".migrated"
BOULDER_MIGRATED_PATH    = ".sisyphus/boulder/.migrated"
BOULDER_V2_BACKUP_SUFFIX = ".v2.bak"
```

### Work File Naming

Work files are named `{work_id}.json` where `work_id` matches `BoulderWorkState.work_id`. The `work_id` is generated by `generateWorkId(planName)` as `{slug}-{8-hex-random}`.

## 3. Type Definitions

### BoulderState (v3)

```typescript
interface BoulderState {
  schema_version: 3
  works: Record<string, BoulderWorkState>
}
```

**Invariant**: `BoulderState` MUST NOT contain any mirror fields. The only top-level keys are `schema_version` and `works`. All work metadata (plan_name, status, session_ids, timestamps, etc.) lives exclusively in `BoulderWorkState`.

### BoulderIndex

```typescript
interface BoulderIndex {
  schema_version: 3
  sessions: Record<string, string>  // sessionID → workID
}
```

**Invariant**: Every session ID in the index MUST correspond to a `work_id` that exists in the `works` directory. The index is a derived cache — it can be rebuilt from work files.

### BoulderWorkState (unchanged from v2)

```typescript
interface BoulderWorkState {
  work_id: string
  active_plan: string
  plan_name: string
  status?: BoulderWorkStatus
  started_at: string
  ended_at?: string
  elapsed_ms?: number
  updated_at?: string
  session_ids: string[]
  session_origins?: Record<string, BoulderSessionOrigin>
  agent?: string
  worktree_path?: string
  task_sessions?: Record<string, TaskSessionState>
}
```

### BoulderStateV2 (legacy, for migration)

```typescript
interface BoulderStateV2 {

  works?: Record<string, BoulderWorkState>
  active_plan: string
```

## 4. Three-Tier API Signatures

### Tier 1: `readBoulderWork(workId)`

Read a single work file by its `work_id`.

```typescript
function readBoulderWork(directory: string, workId: string): BoulderWorkState | null
```

- Reads `.sisyphus/boulder/{workId}.json`
- Returns `null` if file doesn't exist or is corrupt JSON
- Validates that `parsed.work_id === workId` (filename must match content)
- Does NOT touch the index

### Tier 2: `getWorkForSession(sessionId)`

Find which work a session belongs to.

```typescript
function getWorkForSession(directory: string, sessionId: string): BoulderWorkState | null
```

- Reads `.sisyphus/boulder/index.json` for O(1) session→work lookup
- If index has the session, reads the corresponding work file
- If index is missing or doesn't have the session, falls back to scanning all work files (O(n) degraded path)
- Returns the most recently updated work if session appears in multiple works (shouldn't happen, but defensive)

### Tier 3: `listBoulderWorks()`

List all known works.

```typescript
function listBoulderWorks(directory: string): BoulderWorkState[]
```

- Reads all `.json` files in `.sisyphus/boulder/` (excluding `index.json`)
- Returns parsed `BoulderWorkState` objects sorted by `updated_at` descending
- Skips files that fail to parse (corrupt work files are logged, not fatal)

### Additional API

```typescript
function writeBoulderWork(directory: string, work: BoulderWorkState): boolean
function updateBoulderIndex(directory: string, index: BoulderIndex): boolean
function rebuildBoulderIndex(directory: string): BoulderIndex
function deleteBoulderWork(directory: string, workId: string): boolean
```

## 5. Migration Spec (v2 → v3)

### Trigger

Migration runs when:
1. `.sisyphus/boulder.json` exists (v2 file)
2. `.sisyphus/boulder/.migrated` does NOT exist

Migration is triggered on first read or write operation after detecting v2 state.

### Migration Order (strict)

```
1. Read v2 boulder.json → parse as BoulderStateV2
2. Extract works from v2 state (via getBoulderWorks, including mirror→work conversion)
3. Create .sisyphus/boulder/ directory if not exists
4. Write each work to .sisyphus/boulder/{work_id}.json (atomic: .tmp → rename)
5. Build index from work files (scan session_ids arrays)
6. Write .sisyphus/boulder/index.json (atomic: .tmp → rename)
7. Rename .sisyphus/boulder.json → .sisyphus/boulder.json.v2.bak
8. Write .sisyphus/boulder/.migrated marker
```

### Idempotency

- If `.migrated` marker exists → skip migration entirely
- If migration fails mid-way (e.g., crash after step 4):
  - On next run, detect partial state (work files exist but no `.migrated`)
  - Re-run from step 1 (idempotent: work file writes are overwrites)
- The `.migrated` marker is the single source of truth for "migration complete"

### Failure Recovery

| Failure Point | Recovery Strategy |
|---------------|-------------------|
| Step 1-2 (parse v2) | Abort. v2 file is intact. Retry on next operation. |
| Step 3 (mkdir) | Abort. No state written. Retry. |
| Step 4 (write work files) | Partial writes are safe — retry overwrites. |
| Step 5-6 (write index) | Index can be rebuilt from work files. Retry. |
| Step 7 (rename v2 backup) | If rename fails, v2 file still exists. `.migrated` not written. Retry. |
| Step 8 (write marker) | If marker write fails, v2 backup exists, work files exist. On retry, detect partial state and re-run. |

### Post-Migration

After successful migration:
- v2 `boulder.json` is renamed to `boulder.json.v2.bak` (kept for manual rollback)
- All reads/writes use v3 paths
- `BoulderStateV2` type is only used for reading the backup during manual recovery

## 6. Atomic Write Strategy

All writes use the `.tmp` + `rename` pattern to prevent partial writes:

```typescript
function atomicWriteJson(filePath: string, data: unknown): boolean {
  const tmpPath = filePath + ".tmp"
  writeFileSync(tmpPath, JSON.stringify(data, null, 2), "utf-8")
  renameSync(tmpPath, filePath)  // atomic on same filesystem
  return true
}
```

**Rationale**: `rename(2)` is atomic on POSIX filesystems (including APFS on macOS). If the process crashes between `writeFileSync` and `renameSync`, the `.tmp` file is orphaned but the target file is untouched. On next write, the `.tmp` is overwritten.

### Write Order for Work Updates

When updating a work (e.g., appending a session):

```
1. Write work file: .sisyphus/boulder/{work_id}.json.tmp → rename
2. Update index:    .sisyphus/boulder/index.json.tmp → rename
```

The index is always written AFTER the work file. If step 2 fails, the index can be rebuilt from work files.

## 7. Corruption Recovery

### Corrupt Index

If `index.json` is missing, unparseable, or has `schema_version !== 3`:

```typescript
function rebuildBoulderIndex(directory: string): BoulderIndex {
  const workFiles = readdirSync(join(directory, BOULDER_DIR))
    .filter(f => f.endsWith(".json") && f !== BOULDER_INDEX_FILE)

  const sessions: Record<string, string> = {}
  for (const file of workFiles) {
    const work = readBoulderWork(directory, file.replace(".json", ""))
    if (!work) continue  // skip corrupt work files
    for (const sid of work.session_ids) {
      sessions[sid] = work.work_id  // last write wins for duplicates
    }
  }

  return { schema_version: 3, sessions }
}
```

### Missing Work File

If `index.json` references a `work_id` whose file doesn't exist:
- Remove the stale entries from the index
- Log a warning

### Orphan Work File

If a `.json` file exists in `BOULDER_DIR` but is not referenced by any index entry:
- Include it in `listBoulderWorks()` results (it's valid data)
- On next index rebuild, it will be indexed

### Concurrent Write

Two processes writing to the same work file:
- Last `rename` wins (atomic)
- No data corruption (`.tmp` files are per-process)
- Index may be temporarily stale — resolved on next read via rebuild

Two processes writing different work files:
- No conflict (separate files)
- Index updates may race — last index write wins
- Acceptable: index is a cache, can be rebuilt

## 8. Edge Cases

### Empty State

No `.sisyphus/boulder/` directory exists:
- `readBoulderWork()` → `null`
- `getWorkForSession()` → `null`
- `listBoulderWorks()` → `[]`

### Single Work, No Sessions

A work file exists but `session_ids` is `[]`:
- Work appears in `listBoulderWorks()`
- `getWorkForSession()` won't find it (no session to match)
- Index won't have entries for it

### Duplicate Session IDs

A session ID appears in multiple works' `session_ids`:
- Index rebuild: last work processed wins
- `getWorkForSession()`: returns most recently updated work
- This is a data integrity issue — logged as warning

### Work ID Collision

`generateWorkId()` produces a duplicate `work_id`:
- 8 hex chars = 2^32 ≈ 4 billion combinations
- Collision probability is negligible for typical usage (< 1000 works)
- If collision occurs, the new work overwrites the old (acceptable: same plan name)

### Schema Version Mismatch

A work file has `schema_version` other than expected:
- v3 reader encountering v2 work file: attempt to parse, validate required fields
- Future v4 reader: check `schema_version`, run migration if needed

## 9. Validation Rules

When reading a work file, validate:

1. `parsed.work_id` is a non-empty string
2. `parsed.work_id` matches the filename (minus `.json`)
3. `parsed.active_plan` is a non-empty string
4. `parsed.plan_name` is a non-empty string
5. `parsed.started_at` is a valid ISO 8601 string
6. `parsed.session_ids` is an array of strings
7. If `parsed.status` is present, it must be one of: `"active" | "completed" | "paused" | "abandoned"`

Failures: return `null`, log warning. Do not throw.
